## Limitations found in increment 1, updated in increment 3 (honest record, not hidden)
- Prisma CLI validation could NOT run in this environment, in increments 1, 2, or 3. In increment 3, prisma@6.14.0 install succeeded but validate failed with exit 1, ECONNRESET, attemptNumber 1, retriesLeft 2. The schema was instead checked structurally in earlier increments (32 models, 15 enums in increment 2, balanced braces, edition fields present, no em/en dashes in changed files), plus manual review. Do NOT treat the schema as officially validated until prisma validate and a test migration pass on a machine where the engine download works.
- Live PDF export in increment 3 first failed with ENOENT for Helvetica.afm, because Next.js bundled pdfkit. This was fixed by keeping pdfkit, docx, and the template engine external on the server in next.config.mjs, and the live PDF test then passed. Any future Next.js upgrade must retest live PDF export, not only the template engine test, because the failure only appeared in the bundled server route.
- npm install in this workspace fails with a chown EPERM error on package binaries unless --no-bin-links is used. Both package READMEs record this, and npm scripts call binaries by file path so they work either way.
- The first PDF text extraction library tried, pdf-parse, gave flaky and inconsistent parse errors on valid PDFKit output (the same file passed once and failed the next run), while pdftotext and pdfjs-dist read every proof PDF correctly. The test now uses pdfjs-dist 3.11.174 for extraction, and pdf-parse was removed.
- Next.js was first installed at 14.2.18, which npm flagged with a security vulnerability warning. It was upgraded to a patched 14.2.35 release and the build passed again. Check for newer patched releases before any public deployment.

Never mark a feature complete unless it works and has been tested.
